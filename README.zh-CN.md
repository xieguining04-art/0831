# TengYoda Logistics 网站部署包

本包是当前新版网站的静态服务器部署版，正式域名按此前确认的 **https://tengyodalogistics.com** 配置。首页、服务详情和博客文章已生成真实 HTML；动画和中英文切换仍由浏览器中的 JavaScript、CSS 执行。

**只上传 `website` 文件夹里面的内容到网站根目录。不要把整个压缩包的内容都放进公开网站目录。**

## 包内文件

| 文件或目录 | 用途 | 是否上传到公开网站目录 |
| --- | --- | --- |
| `website/` | 可直接托管的页面、图片、样式、脚本、站点地图和 404 页面 | 上传其内部全部内容 |
| `source/` | 完整维护源码、依赖锁文件和静态打包脚本 | 否，保存在开发电脑或非公开目录 |
| `deployment/` | 可选 Nginx / Apache 配置示例 | 否，按服务器类型手动配置 |
| `validation-report.json` | 本次生成的页面、资源和配置校验结果 | 否 |
| `SHA256SUMS.txt` | 包内文件的 SHA-256 校验值 | 否 |

## 上传步骤：宝塔 / Nginx / Apache

1. **先备份旧站。** 下载或保留原网站文件、网站配置；原站如果有数据库，也一并备份。不要先清空旧站。这个新版网站不需要新建数据库，但并不代表可以删除旧站数据库。
2. 为新版建立独立网站目录，例如 `/www/wwwroot/tengyodalogistics-new`。把 `website/` 内的全部文件上传到这个目录。目录第一层必须能看到 `index.html`，以及 `assets`、`images`、`services`、`blog` 等目录。不要多套一层 `website`。
3. 在控制面板中，把该域名的网站根目录设为新版目录，默认首页设置为 `index.html`。静态版不需要运行 Node.js、PHP 或启动数据库。不需要在服务器上执行 npm 命令。
4. 保留或安装该域名的 HTTPS 证书。域名的 DNS 应指向你的服务器。若 DNS 还没切换，可先用服务器提供的临时测试地址检查展示；临时地址不会记录本包的正式域名 GA4 统计。
5. 按下方清单检查后再完成正式切换。若出现异常，将网站根目录切回备份的旧站目录即可回退。不要把新旧版本文件混合上传，以免残留旧页面和脚本。

本包假定部署在域名根目录，而不是 `https://域名/newsite/` 等子目录。页面使用 `/assets/...` 这类根路径资源地址。请通过 HTTP/HTTPS 打开网站；直接双击本地 HTML 文件不能用于验证完整效果。

### Nginx / 宝塔 Nginx

普通静态站配置通常可直接显示本包。`deployment/nginx-locations.conf.example` 提供目录页面、404 和缓存规则。将规则合并到已有的该域名 `server` 配置中，**替换重复的 `location /`，不要盲目覆盖整份配置**。HTTPS 证书和网站根目录继续使用你服务器自己的配置。

在有服务器配置管理权限的情况下，修改后先运行 `nginx -t`，通过后再重载。若由宝塔管理，可用面板的配置检查、保存和重载功能。不要套用把所有不存在地址转到首页的单页应用规则；本包的每个服务页和文章页都有独立目录与 HTML 文件。

### Apache

使用 `index.html` 作为默认首页即可打开目录页面。若需自定义 404 和缓存，可参考 `deployment/apache.htaccess.example`，在确认服务器允许相应 `.htaccess` 指令后，将它作为 `website` 根目录中的 `.htaccess` 使用。

如果加入 `.htaccess` 后出现 500，撤回新加入的 `.htaccess`，请服务器管理员把相应规则配置在虚拟主机中。不要反复修改页面文件来处理服务器权限问题。

## 源码维护与再次打包

仅在开发电脑上使用本节。需要 Node.js 22.13 或更高兼容版本，以及 Linux / macOS 兼容终端中的 Bash、GNU `timeout`、`zip`、`unzip`。Windows 可使用 WSL。源码保留原有构建结构及锁文件。

进入解压后的 `source` 目录，安装锁定依赖并生成新部署包：

```bash
npm ci
node scripts/package-static.mjs
```

脚本会使用现有构建工具静态生成全部页面，校验资源和链接，然后在 `outputs` 下创建新 ZIP。不会连接服务器，不会发布当前预览站，也不会修改 DNS。脚本如报告错误，不应部署半成品目录。

常见修改位置：`lib/company.ts` 为联系资料；`lib/services.ts` 为服务内容；`lib/blog-posts.ts` 为博客；`lib/seo.ts` 为 SEO 文案；`public/images` 为图片；`app/globals.css` 为样式。

若更换正式域名，先更新 `lib/analytics.ts` 的生产域名允许列表，再使用新域名构建，并相应更新部署说明：

```bash
NEXT_PUBLIC_SITE_ORIGIN=https://your-new-domain.com node scripts/package-static.mjs
```

不能仅修改压缩包名称或 DNS，就认为全部 SEO 配置已变更。
